## Гипотезы

| № | Гипотеза | Статус на 14.08 |
|---|---|---|
| H1 | Более 3 параллельных TLS к одному SNI → заморозка | **подтверждена**: 6 параллельных = 0 из 6 (малина) |
| H2 | Заморозка длится ~120 с | не проверена (после 90 с + одиночный запрос прошёл) |
| H3 | Заморозка привязана к SNI, а не к адресу | не проверена |
| H4 | Обрыв на ~15 КБ зависит от скорости передачи | **опровергнута**: малина 2.3 МБ/с, 10 МБ целиком |
| H5 | Обрыв зависит от TLS-фингерпринта клиента (macOS vs Linux) | **новая, приоритетная** |
| H6 | Фильтрация зависит от времени суток / нагрузки ТСПУ | не проверена |
| H7 | Фильтр применяется только к Cloudflare, свои ноды чистые | частично: ноды отвечают, но объём не проверен |
| H8 | Ограничения различаются по операторам (дом vs офис) | **подтверждена**: офис чист, дом под фильтром |
| H9 | UDP/QUIC наружу режется, особенно на 443 | не проверена с домашнего канала |
| H10 | Блокировка асимметрична (вход/выход) | не проверена |
| H11 | Порог обрыва — ровно ~15–16 КБ и не зависит от размера запроса | частично: 15115/15632/15111 |
| H12 | Популярный SNI (apple.com, yandex.ru) хуже своего | не проверена |

## Тесты

### Блок 1 — приоритетные, закрывают спорное

#### T1. Фингерпринт: macOS против Linux на одном канале (H5)

Самый важный тест. Оба клиента на одном канале, один URL, одинаковая нагрузка.

На **MacBook** (VPN выключить) и на **малине** одновременно:

```bash
for i in $(seq 1 15); do
  curl -sS -o /dev/null --max-time 8 \
    -w "$i %{remote_ip} получено=%{size_download} t=%{time_total}\n" \
    "https://speed.cloudflare.com/__down?bytes=100000"
done
```

Затем на MacBook то же самое, но чужим TLS-стеком — если стоит homebrew curl
(OpenSSL), сравнить с системным:

```bash
/opt/homebrew/opt/curl/bin/curl --version | head -1   # должен быть OpenSSL
```

**Что подтверждает:** если системный curl рвётся, а OpenSSL-сборка на той же
машине — нет, гипотеза H5 верна, и дело в фингерпринте, а не в канале.

#### T2. Порог параллельности (H1, уточнение)

На малине, серии по возрастанию, с паузой 150 с между сериями:

```bash
for n in 2 3 4 5; do
  echo "=== $n параллельных ==="
  for i in $(seq 1 $n); do
    curl -sS -o /dev/null --max-time 8 \
      -w "n=$n #$i получено=%{size_download} t=%{time_total}\n" \
      "https://speed.cloudflare.com/__down?bytes=100000" &
  done
  wait
  sleep 150
done
```

**Что даёт:** точную границу. Известно, что 1 проходит, 6 убивает.

#### T3. Длительность заморозки (H2)

Сразу после срабатывания (6 параллельных) — одиночные пробы каждые 15 с:

```bash
for i in $(seq 1 6); do curl -sS -o /dev/null --max-time 8 \
  -w "t+$((i*15))с получено=%{size_download}\n" \
  "https://speed.cloudflare.com/__down?bytes=100000"; sleep 15; done
```

**Что даёт:** реальную длительность против заявленных 120 с.

#### T4. К чему привязана заморозка: SNI или адрес (H3)

Сразу после срабатывания проверить три цели:

```bash
curl -sS -o /dev/null --max-time 8 -w "тот же SNI: %{size_download}\n" \
  "https://speed.cloudflare.com/__down?bytes=100000"
curl -sS -o /dev/null --max-time 8 -w "другой SNI, тот же CDN: %{size_download}\n" \
  "https://cloudflare.com/cdn-cgi/trace"
curl -sS -o /dev/null --max-time 8 --insecure -w "своя нода: %{size_download}\n" \
  "https://167.104.104.209/"
```

**Что даёт:** заморожен SNI, адрес назначения или весь TLS-трафик клиента.

### Блок 2 — свои серверы как приёмная сторона

#### T5. Где именно рвётся (H10)

На **hhh-sto-01** запустить ограниченный захват:

```bash
timeout 60 tcpdump -nn -i any -c 200 'host <IP клиента> and port 443' -w /tmp/cap.pcap
```

С **MacBook** в это же время — скачать крупный объём. Затем сравнить:
сколько байт клиент получил и сколько сервер реально отправил.

**Что даёт:** ответ на вопрос, обрывает ли ТСПУ поток к клиенту (сервер шлёт,
клиент не получает) или душит запрос. Это единственный способ увидеть разрыв
с обеих сторон — против Cloudflare он недоступен.

#### T6. Свои ноды: есть ли «штора» на них (H7, H11)

Поднять на **hhh-sto-02** временную раздачу файла (traefik уже слушает 443,
wildcard-серт есть). Скачать с MacBook, малины и офиса файлы разного размера:

```bash
for sz in 10k 14k 16k 20k 50k 1m 10m; do
  printf '%-6s ' "$sz"
  curl -sS -o /dev/null --max-time 20 \
    -w "получено=%{size_download} скорость=%{speed_download}\n" \
    "https://<имя>.cosmdandy.dev/test-$sz.bin"
done
```

**Что даёт:** порог обрыва на *своей* инфраструктуре и ответ, специфична ли
фильтрация для Cloudflare. Заодно проверяется H11 — точная граница.

#### T7. UDP и QUIC наружу (H9) — критично для Hysteria2

На **hhh-sto-01** поднять слушателей на двух портах:

```bash
# на ноде, в двух tmux-окнах
nc -u -l -p 443    # то, что режут оптом
nc -u -l -p 39443  # произвольный высокий
```

С MacBook и малины отправить пакеты на оба, на ноде смотреть `tcpdump`.

**Что даёт:** прямой ответ, взлетит ли Hysteria2 и на каком порту. Сейчас это
чистая догадка на основе чужих отчётов 2022 года.

### Блок 3 — сравнение операторов и условий

#### T8. Один тест со всех четырёх точек (H8)

T1 повторить синхронно с MacBook, малины, офисного pve-1 и — как контроль
«извне» — с hhh-ams-01. Пятая колонка нужна, чтобы отделить проблемы канала
от проблем самого Cloudflare.

#### T9. Три источника из одной офисной сети (H8)

Запустить параллельные серии с `pve-1`, `pve-2`, `pve-3` одновременно:
проверить, считается ли порог параллельности на адрес или на подсеть.

**Что даёт:** если три машины по 2 соединения каждая (итого 6) не ловят
заморозку, а одна машина с 6 ловит — счётчик привязан к адресу источника.

#### T10. Время суток (H6)

Малина, автономно: T1 каждый час в течение суток, вывод в файл.

```bash
# cron на малине
0 * * * * /tmp/probe-cf.sh >> /var/log/probe-hourly.log 2>&1
```

**Что даёт:** ряд наблюдений вместо точечных снимков. Это то, ради чего
малина и нужна.

#### T11. Влияние SNI (H12)

С MacBook и малины — одинаковые запросы к своей ноде с подменой SNI:

```bash
for sni in apple.com yandex.ru dl.google.com hy-sto.cosmdandy.dev; do
  printf '%-24s ' "$sni"
  curl -sS -o /dev/null --max-time 8 --insecure \
    --resolve "$sni:443:167.104.104.131" \
    -w "получено=%{size_download}\n" "https://$sni/"
done
```

**Что даёт:** проверку совета из ntc.party не использовать популярные SNI.

### Блок 4 — что видно снаружи

#### T12. Профиль нод глазами сканера

Проверить, что показывают о наших адресах публичные сканеры (Censys/Shodan
через веб), и сверить с фактическим списком портов: `22`, `2222`, `443`,
`2054`, `2084`, `2444`, `2446` + высокие UDP.

**Что даёт:** понимание, насколько машины похожи на VPN-ноды со стороны.
